# Game Café Scheduling Under Conflict Cascades

## Question

Can bin-packing optimization for table-slot scheduling detect which games create **temporal incompatibility** (players checking out one game prevents others from forming viable sessions) by analyzing constraint-violation patterns, without direct co-rental data?

## The Non-Obvious Angle

Standard bin-packing assumes items are interchangeable and that packing failures arise from volume alone. Here, the **failures themselves encode information about game incompatibility**:

- When games A and B are frequently checked out in overlapping time windows, they compete for the same players and tables.
- A greedy scheduler with limited tables will *fail to pack* these concurrent checkouts.
- By clustering which games co-appear in failed placements, we recover the latent incompatibility structure *without* ever seeing explicit "games A and B were played together" data.

## Method

1. **Greedy bin-packing** assigns checkouts to 3 tables, respecting temporal overlap and player-count capacity.
2. **Track failures**: which checkout indices couldn't be packed?
3. **Extract signatures**: for each failed checkout, record which other games were checked out nearby (1-hour window).
4. **Co-occurrence counting**: measure how often pairs of games appear together in conflict signatures.
5. **Inference**: game pairs with high co-conflict counts are incompatible.

## Limitations

- **Synthetic**: ground truth incompatibility is designed in; real-world validation would require comparing inferred pairs against actual player surveys or co-rental logs.
- **Simple scheduling**: real café scheduling is more complex (table types, game duration, player skill matching, etc.).
- **Noise**: incompatible pairs must be frequent enough to generate detectable conflict patterns; rare incompatibilities may be missed.
- **Causality**: high co-conflict doesn't prove incompatibility—it could arise from coincidental demand spikes. Real validation needs domain knowledge.
